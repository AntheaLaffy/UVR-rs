# DeEcho 与 RoFormer CPU 模块比较

日期：2026-09-10。Candle CPU 与 Burn Flex 均通过 8 个新增样本的形状与逐元素检查。与 [5-HP 卷积实验](2026-09-10-vr-cpu-blocks.md) 合并看，当前选择 Burn Flex 做首个完整 5-HP 网络原型；这是下一步实验的选择，整模型性能与最终部署方案尚未确认。

| 模块／输入形状 | Candle 热运行中位数（范围）ms | Burn Flex 热运行中位数（范围）ms |
| --- | --- | --- |
| DeEcho 低频双向 LSTM `[160,1,168]`，hidden=64 | 2.378（2.284–2.465） | 1.445（1.432–1.454） |
| 同一 LSTM 的短序列／双批次 `[7,2,168]` | 0.229（0.218–0.379） | 0.165（0.165–0.169） |
| DeEcho 高频双向 LSTM `[160,1,168]`，hidden=32 | 1.539（1.489–1.703） | 0.958（0.956–0.964） |
| DeEcho 全频双向 LSTM `[160,1,336]`，hidden=64 | 2.533（2.432–2.639） | 2.205（1.986–2.832） |
| 1296 时间注意力 `[2,801,512]` | 157.588（153.165–165.749） | 128.806（127.686–129.321） |
| 1296 频率注意力 `[16,62,512]` | 23.700（22.780–25.584） | 47.589（46.118–48.029） |
| 1296 注意力零输入 `[1,3,512]` | 0.384（0.239–0.458） | 0.415（0.410–0.419） |
| 1296 时间前馈 `[2,801,512]` | 51.720（51.371–53.523） | 44.495（44.095–45.854） |

LSTM 最大绝对误差不超过 `6.7801e-7`，注意力不超过 `4.7684e-6`，前馈不超过 `1.7167e-5`；零输入注意力输出与参考同为零。检查阈值仍为 `1e-3 + 1e-4 * abs(reference)`，每次执行均检查，未因结果调整阈值。

两套 Rust LSTM 都按 PyTorch 的 i/f/g/o 排列实现单层双向递归，提前计算全部输入投影，初始 hidden/cell 为零；没有调用框架融合 LSTM。RoFormer 注意力包含 L2 归一化形式的 RMSNorm、QKV 投影、相邻元素成对 RoPE、稳定 Softmax、head 门控和输出投影；前馈包含精确 GELU 与两次带偏置投影。RoPE 缓存由 Rust 根据实际旋转频率构造，缓存准备不计时，应用旋转计时。Rust 注意力物化完整分数矩阵，参考 PyTorch 使用固定实现中的 SDPA；这里比较数学结果，不声称复刻参考的融合内核。

RoFormer 输入来自 352800 样本的确定性立体声合成音频、严格加载的真实 1296 权重。第一层时间注意力／前馈的完整输入是 `[62,801,512]`，频率注意力是 `[801,62,512]`。实验分别取 2 个频带、16 个时间条目，保留完整序列长度；批次条目彼此独立。测量不能直接当作完整 8 秒音频耗时或 RTF。短序列双批次和零输入是正确性边界样本。

构建、参考与测量边界：

- 基线 `b5418ed` 加本轮未提交变更；rustc 1.98.1、x86_64 Linux、默认 release、未设置 RUSTFLAGS。
- Candle 0.10.2 CPU（default-features=false）、Burn Flex 0.21.0（std、SIMD、Rayon），FP32、`RAYON_NUM_THREADS=2`，顺序运行。
- Cargo.lock SHA-256：`c70ca0c1ad53dbbc6e696fe93cc9263ceb68010bbce08a64ff4f64abdc9d0c89`；验证 uv.lock：`2590ac3d78e0974aab908c11ba8a1a6bc4ab78a0ed38902e1382576a4edddc04`，PyTorch `2.13.0+cpu`。
- 样本清单 SHA-256：`79d559d07382e4ec4674a4f071c53dabbfc3c23ca513bc03b6705af9dbe17228`。清单记录输入、权重、输出各张量的 SHA-256、形状、严格加载报告的摘要，以及固定的上游实现和配置。
- 计时包括 CPU 操作、临时张量和输出物化；排除文件 I/O、初始张量与旋转缓存准备。首次执行另记，额外预热 1 次后采集 5 次。未控制其他应用和文件系统缓存。
- 原始样本与首次耗时：`benchmarks/artifacts/backend-probe/sequence-{candle,burn}.json`。整个进程峰值 RSS 为 Candle 229336 KiB、Burn 183016 KiB；包括参考张量驻留，不能视为单模块额外内存。
- 本机硬件、系统、电源模式和工具链记录继续只放在 Git 忽略的本地 artifacts 目录。

复现见 [探针说明](backend-probe/README.md)。这些结果没有证明完整 RoFormer／DeEcho 已在 Rust 中实现，也没有覆盖音频听评、Windows、客户硬件或最终性能验收。
