# 1296 CPU 推理优化实验

日期：2026-09-11。按 [工程基线 v1.2](../docs/baseline.md) 继续优化 1296；网络使用原始权重和 FP32，正向 STFT 保持 v1.1 的 float64。以下区分采样、真实中间张量的重复测量与完整波形验证，尚不构成整曲或处理链性能验收。

## 完整窗采样

基线二进制在 8 线程、系统调度下运行同一份 8 秒完整窗，使用 `perf record -e cycles:u -F 99 -g`。本次网络单次耗时 310.015 秒，进程含加载共 314.57 秒，user／sys 为 672.05／36.78 秒，平均占用约 2.25 个逻辑 CPU，峰值 RSS 991236 KiB。采样包含模型加载，且有 profiler 开销，不能与其他日期的单次记录直接计算线程加速比。

性能核约 47K 样本：GEMM 主内核占 36.38%，`StridedIter::next` 占 14.06%，形状维数查询占 6.12%，通用 strided 乘法遍历占 5.74%。GELU 的 erf／exp 和串行逐元素循环也在主要热点中。能效核约 23K 样本中 GEMM 主内核占 75.68%。两类 PMU 分开报告，不将这些比例当作墙钟阶段占比。

该结果与源码一致：频繁拆分偶数／奇数特征、广播、拼接会触发通用布局遍历；Flex 0.21 的 GELU 在单线程循环中执行。增加线程预算不能自动展开这些路径。

## 保持计算顺序的融合

- RoPE 直接读取相邻元素对，计算 `even*cos - odd*sin` 和 `odd*cos + even*sin`，按原顺序写回；避免偶／奇切片广播与拼接临时张量。
- RMSNorm 保留原后端的平方、求和、开方和最小值截断，随后一次遍历完成除长度、乘维数平方根、乘 gamma。没有改变归约顺序或把参数重关联。
- GELU 仍调用当前后端同一个 `libm::erff`，保持 `0.5*x*(1+erf(x/sqrt(2)))`，只把独立元素分派给现有 Rayon 池；小张量保留串行循环。

独占连续存储原地更新，共享或非连续视图通过 Flex 的写时复制与布局转换保护。没有新增 unsafe、近似 GELU、低精度或全局 fast-math。三个内核测试逐位对照旧运算，覆盖共享／偏移／转置视图、静音与低能量归一化、RoPE 缓存切片，以及 GELU 的大小张量与独占缓冲复用。

## 真实中间张量对照

使用原有 `sequence` 清单中的真实第一层激活和权重，序列长度为时间 801、频率 62；独立 batch 条目取 2／16。每组均为首次执行、额外预热、五次热运行，七次全部通过原模块门限。相同二进制先测基线，再分别启用 GELU、RMSNorm、RoPE，随后测组合，最后重测基线；2 线程与 8 线程顺序执行。

下表为热运行中位数（毫秒）：

| 线程／模块 | 基线开始 | 三项组合 | 基线结束 |
| --- | --- | --- | --- |
| 2／时间注意力 | 412.346 | 274.501 | 383.131 |
| 2／频率注意力 | 153.072 | 74.769 | 166.447 |
| 2／时间前馈 | 136.109 | 111.954 | 134.707 |
| 8／时间注意力 | 328.598 | 214.416 | 348.773 |
| 8／频率注意力 | 128.860 | 63.012 | 165.195 |
| 8／时间前馈 | 102.249 | 96.811 | 127.881 |

单独 RoPE 在 8 线程的时间／频率注意力中位数为 236.321／68.261 毫秒，支持其为主要收益来源；RMSNorm 单项和前馈收益较小，且有环境波动，不能把组合加速按单项相乘。表中是完整模块，不是完整网络或 RTF。所用模块输入是保存后重新加载的连续张量；实际整网还有频率／时间转换与切片，需用完整波形测量确认收益。

## OpenVINO 模块候选

直接加载核验过的原始 1296，从其第一层取时间／频率注意力及前馈，转换固定 shape。OpenVINO `2026.3.1-22476`、CPU、FP32、8 线程、单 stream，实际不绑核、不启用超线程、允许所有核心类型。每个模块先核对原 PyTorch 输出，再验证 OpenVINO 的七次输出。

| 模块 | 热运行中位数（范围）ms | 最大绝对误差 |
| --- | --- | --- |
| 时间注意力 | 83.829（74.095–89.329） | `2.3842e-6` |
| 频率注意力 | 33.653（30.746–43.324） | `4.7684e-6` |
| 零输入注意力 | 0.724（0.654–0.886） | 0 |
| 时间前馈 | 92.838（78.756–147.952） | `1.3351e-5` |

计时包含输入／输出复制，排除转换、编译、参考 I/O 和验证。运行图包含 FP32 AVX2 子图、`gemm_mlas_f32` 和 `brgemm_avx2_f32` 全连接内核。注意力的结果支持继续研究成熟后端，前馈则没有稳定领先结论；实际核心调度不同。后续完整网络 PCM 与 Rust 调用见 [OpenVINO 完整后端实验](2026-09-11-roformer-openvino.md)，原权重加载到此后端的产品路径仍待接入。

原始产物在 `benchmarks/artifacts/2026-09-11-roformer-performance/`：采样与资源记录、`modules-*.json/.time/.log`、`module-runs.json`、`openvino-t8.json`。源码、锁文件与二进制摘要由 `baseline-sha256.json`、`candidate-sha256.json` 保存，两个版本及隔离的基线构建均保留。编译使用现有 rustc 1.98.1 默认 release、Burn Flex 0.21.0，没有 native／LTO 覆盖；硬件与电源配置沿用 [VR 实验](2026-09-11-vr-cpu-optimization.md) 的本机快照。

## 完整波形验证

三组原始短网络和四组完整短 PCM 检查通过，包括静音、单采样、重采样与窗内取消。8 线程的同一份完整 8 秒输入单次耗时 212.574 秒；逐样本、双声道整轨 RMS 门限均通过，输出与先前保留的 Rust 基线逐字节相同，摘要记录在 `full-output-identity.json`。真实 3 秒片段的双轨 PCM 也已通过原门限。

该真实片段的 8 线程 release CLI 同时通过双轨 WAV、重复执行拒绝覆盖、Ctrl-C 和无部分输出检查；取消延迟 0.5643 秒，报告在 `cli-after-t8/report.json`。这次文件验证和计时数据早于 RoPE 迭代器改为 `as_chunks_mut::<2>` 的机械清理；清理后 core／CLI 的 32 项 release 测试、两个 workspace 的 Clippy 通过，不能把旧二进制摘要当作清理后的产物身份。

完整窗进程峰值 RSS 为 991092 KiB，未较基线采样记录明显下降；user／sys 为 704.36／38.46 秒，平均 CPU 约 341%，CPU 总时间没有同步降低。按进度间隔汇总的 Transformer 时间约 209.203 秒，其中时间分支 124.347、频率分支 84.856 秒；这些间隔含邻接拼接等工作，不是单算子的独占计时。

本次完整窗是一次正确性运行；310.015 秒的旧版记录含 profiler，不能据两次单值宣称稳定提升 31%。完整窗的首次／预热／五次热运行与同资源 Python 对照仍需补齐。四套模型、默认窗口完整 PCM、整曲、处理链、最佳线程／编译配置和 GPU 继续验证。
