# VR 文件处理与真实片段对照

日期：2026-09-11。5-HP、6-HP、DeEcho 三套 CLI 文件处理均通过固定参考对照。输入来自本机音频 60 秒处的 3 秒片段：44.1 kHz、单声道、132300 个采样；Rust 输出每轨为双声道、相同采样数的浮点 WAV。素材及文件摘要仅保存在被忽略的本地实验目录。

采用 [工程基线 v1](../docs/baseline.md) 的原始权重、CPU FP32、2 线程、512 帧窗口。验证工具将独立解码的 PCM 写成含中文与空格文件名的 WAV，启动 release CLI 后逐样本比较两轨。Rust 子进程的完整环境只有 `PATH=/nonexistent` 和 `RAYON_NUM_THREADS=2`，加载、解码、推理、编码不调用 Python。

| 模型 | 主轨最大误差 / RMSE | 残余轨最大误差 / RMSE | 网络窗口 |
| --- | --- | --- | --- |
| 5-HP | 2.4214e-7 / 1.6386e-8 | 2.2724e-7 / 1.6516e-8 | 2 |
| 6-HP | 1.9372e-7 / 1.2842e-8 | 1.6764e-7 / 1.3288e-8 | 2 |
| DeEcho | 8.9407e-8 / 8.2973e-9 | 4.4005e-8 / 1.6402e-9 | 1 |

全部通过工程基线的逐样本与每轨 RMS 门限，未单独归一化、移动时间轴或裁去边界。三套重复执行都拒绝覆盖既有文件，原有字节未变。5-HP 另在进入网络后发送 SIGINT，退出码为 130、无正式输出；取消耗时 **15.161 秒**，因为当前 VR 网络只在窗口之间检查取消，仍需改善交互响应。

文件编解码由独立 SoundFile / libsndfile 的 8 组自制样本验证，包括 WAV 整数／浮点、FLAC、MP3 和 gapless 长度。Rust 解码器拒绝空、非有限、多声道和可检测的截断文件；输出临时文件在取消时清理，发布时拒绝覆盖竞态。完整本地 MP3 也已用 Rust 解码得到 13648302 个有效采样，与独立解码的长度一致。
