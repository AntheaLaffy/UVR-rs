# 工程基线 v1.3

决定日期：2026-09-10。用户说明客户没有提供参考基线，并授权本项目自行决定。以下是实现和验收所用的工程约定，不代表复刻某个未提供的客户安装包。后续修改须记录原因、参数差异和重新验证的范围。

2026-09-11 修订 v1.2：按用户明确要求，撤销允许 Rust 热运行慢于 Python 参考的性能验收标准。目标是充分利用硬件与推理后端，把四套模型及完整处理链的同质量性能持续压到可验证的极限。固定两线程用于对照，不限制最终线程、batch 或设备配置。本次仅修订性能目标；下述权重、音频语义和数值门限沿用 v1.1，既有正确性样本继续有效。

2026-09-12 修订 v1.3：用户明确要求在机器内存能够承受的范围内以速度优先，撤销 VR 4 GiB／1296 8 GiB 的固定 RSS 验收上限。允许为更快的内核、更大 batch、权重预打包、工作缓冲和缓存增加内存；但每一笔额外内存都必须能归因于有效缓存、预打包数据、复用 scratch 或并行在途激活，并在完整任务墙钟、RTF 或稳定吞吐上给出可重复的收益。只增加 RSS、复制、调度或带宽压力而不提速的内存属于无效占用，不得采用；按实际可用内存及系统余量选择配置。权重、音频语义和质量门限不变。

2026-09-11 修订 v1.1：1296 的正向频谱改为 float64 窗乘法与 FFT，再转 complex64 进入 FP32 网络；ISTFT 保持 FP32，使用同一 float64 周期 Hann 系数转成 float32。原 FP32 STFT 在低能量频带的舍入差异会被 RMSNorm 放大，已在原始网络中复现完整窗误差超限，见 [定位记录](../benchmarks/2026-09-11-roformer-numerics.md)。独立参考同步选择此计算精度，门限保留，新样本单独生成，原失败记录保留。该修订只涉及 1296 的频谱精度；同一完整 8 秒窗口、短输入和真实片段 CLI 已通过原有门限，跨窗仍需验证。

## 参考与运行边界

- 三套 VR：UVR `5517e0cf0d1acd16a1618eeedec596957523f9e1` 的 `nets`／`nets_new` 及多频带处理函数。
- 1296：python-audio-separator `bf1164aa0f1ee1d1d0ef0f09b315f7659fc06bab`，配置、源码与权重摘要见 [参考来源](references.md)。
- Python 只用于独立参考验证。产品由 Rust 加载原始权重并执行音频处理；GUI 沿用 Tauri／TypeScript。
- 首个验收平台为 Linux x86_64；CPU FP32、batch=1、2 个计算线程作为可重复的固定资源对照，硬件快照放本地实验产物。最终配置须实测线程、核心调度、batch、后端及可用设备的最优组合。Burn Flex 0.21.0 是当前实现后端，后端选择仍受性能证据检验；可用 GPU 与其他系统分别建立记录。
- 权重由使用者提供本地文件并核验身份；首版不将第三方权重捆绑分发。

## 音频与参数

第一组可重复音频对照使用 44.1 kHz 双声道 FP32 PCM。单声道复制到左右声道，其他采样率先转换为 44.1 kHz；超过双声道的输入返回明确错误，避免隐含混音规则。输出为双声道、44.1 kHz、32 位浮点 WAV，保留增益，不独立归一化或硬削波。时长按采样率转换后向上取整；分块前补零、合并后裁回这个精确长度。空输入拒绝，静音输出全零。

三套 VR 保留各自已经核验的频带、FFT、hop、声道变换与新旧滤波规则。基础预设固定窗口 512 帧、batch=1、TTA 关闭、aggressiveness=0、伪影后处理关闭、高频 mirroring 关闭。窗口左右上下文为 HP 的 128 帧和 DeEcho 的 64 帧。幅度按整段频谱最大值归一化；每窗独立重置 LSTM 状态。两轨分别用掩码及其补集重建，记录与输入的重建残差，不把残差强制加到某轨来隐藏频带损失。

重采样统一采用 SciPy 1.16.3 `resample_poly` 默认 Kaiser β=5、20 倍最大升降采样因子加 1 个抽头、零边界填充的确定性定义，使用 Rust 实现；因子先约去最大公约数。它与 VR 配置的低频带 `polyphase` 一致；入口采样率转换及重建也显式选用它，取代上游随平台变化的 `kaiser_fast`／`sinc_fastest` 默认。参考程序同样设置该参数。不能将此预设称为所有 UVR 默认输出的逐样本复刻。

VR DSP 参考固定 librosa 0.9.2（与固定 UVR requirements 一致），其 STFT 为居中 constant padding 和周期 Hann。NumPy 2.2.6 环境只在独立验证进程恢复旧版 librosa dtype 表需要的 Python 类型别名，并固定 setuptools 80.9.0 提供旧版资源接口；这些兼容措施没有替换数值算法，也不进入产品运行时。

1296 保留发布配置：44.1 kHz、FFT 2048、hop 441、chunk 352800、重叠数 4，输出人声，伴奏用重采样后的原输入减人声。2026-09-11 固定调度如下：输入末尾补零到完整 hop，至少 1323 个采样，确保反射 STFT 合法且原网络 ISTFT 不丢尾部。窗口步长 88200；沿用固定参考 `_roformer_chunk_starts`，最后一窗对齐补齐后的末尾、只执行一次，短于 8 秒时直接处理补齐后的短窗。使用 SciPy `signal.windows.hamming(352800)` 的对称 Hamming（float64 计算后转 float32），按实际窗口输出长度取其前缀，加权累加后除以相同权重之和，裁回重采样后的精确长度。静音跳过网络，其他输入不做增益归一化或移调。

上述调度保留固定参考的步长、尾窗和交叠权重；完整 hop 补零、极短输入补到 1323、关闭入口／逐轨归一化是本项目明确选择的边界约定。固定参考直接处理任意短输入时可能反射填充失败或丢失不足一个 hop 的尾部，因此不能将其行为作为边界验收。参考生成器同样先执行这些约定，再调用原模型与原调度函数。整曲正确性与性能仍需验证。

基础预设用于先贯通可验证的音频链。TTA、aggressiveness 和高频处理随后分别增加对照；处理链先按 1296 → 5-HP 或 6-HP → DeEcho 接通，同时保留逐模型输出，用同一素材比较去和声／去混响顺序。模型输出标签依据元数据，主唱／和声语义还须音频验证，不能凭文件名宣称听感。

## 数值与质量验收

下列门限在完整音频对照前固定。对照双方使用相同权重、参数和解码后的 PCM；不得分别归一化、移动输出时间轴或放宽门限后省略失败记录。

| 对象 | 验收条件 |
| --- | --- |
| 权重 | 整文件摘要匹配；所有张量名称、形状、类型和有限值通过严格检查 |
| STFT／ISTFT | 保留已有频谱 `8e-5 + 2e-5 × abs(reference)`、波形 `2e-6 + 2e-5 × abs(reference)` 逐元素门限 |
| 重采样及多频带 DSP | 频谱沿用上述 STFT 门限；重建波形 `1e-5 + 2e-5 × abs(reference)`，形状精确一致 |
| 完整掩码 | `1e-3 + 1e-4 × abs(reference)`，同时报告最大误差与 RMSE |
| 完整音频 | 每样本误差 `≤ 2e-4 + 2e-3 × abs(reference)`；误差 RMS `≤ 1e-3 × max(参考 RMS, 1e-4)`；声道和采样数完全一致、全有限 |
| 边界 | 静音严格为零；覆盖单采样、短于窗口、恰好窗口、非整数窗口、首尾脉冲、单／双声道和重采样 |
| 音质 | 保存逐轨试听产物和残差信息；数值一致不等于用户已认可音质，没有真值时不报告模型 SDR 排名 |

参考实现的异常行为单独处理：`inference_vr` 对全零幅度直接除以最大值会得到非有限数，本基线在归一化前返回全零音频；频带重建必须将未覆盖频点初始化为零，上游 `np.ndarray` 的未初始化内容不构成可重复参考。验证工具应记录这些差异并用边界样本核验，不直接修改参考子模块。

## 性能与产品验收

性能目标是最大化同质量推理效率：四套指定权重及完整处理链都要持续降低热运行耗时与 RTF，并优化冷加载、首个结果、取消延迟、峰值内存、分配和数据搬运。原权重、音频语义和质量门限是硬约束。运行时采用 Rust 本身不构成性能成果，所有收益须来自完整任务实测。

固定 Python 实现提供同资源对照；Rust 在相同输入、预设和资源预算下仍慢于参考的路径，不得标为性能验收通过。超过参考后仍须继续优化已测出的主要热点，不能把达到某个参考倍率当作调优结束。另报同机最佳配置的对照，为双方分别选择合理的线程、batch 和可用后端，明确各自资源与参数；最终产品配置不受两线程基线限制。

调优完成须有四套模型、默认窗口、短／长音频、整曲和完整处理链的证据：主要瓶颈已重新采样；适用的内核、布局／融合、缓存／缓冲、并行调度、编译和成熟 CPU／GPU 后端方向已有可复现实验结论；有收益且通过质量门限的方案已进入实际 CLI／GUI 共用路径。剩余限制、无收益或被质量／资源约束排除的候选须记录原因与测量，不能用未测的“可能很快”或局部算子加速代替完成证明。

速度优先于压低内存数字，但不是“内存越多越快”的豁免。只要实际可用内存足以容纳任务，并为操作系统、GUI 和其他活动进程保留余量，就允许用更多内存换取完整任务加速；候选必须说明新增内存的用途，并以相同输入的重复测量证明墙钟、RTF 或稳定吞吐改善。权重预打包、计划／复用缓存、并行在途激活和减少搬运的 scratch 属于有效提速缓存；仅增加 RSS、复制、调度和带宽压力却没有可重复收益的分配属于垃圾占用，应删除或缩小。不能仅因超过原来的 4／8 GiB 阈值拒绝已证明有效的候选。记录峰值 RSS、系统可用内存、共享设备内存及内存压力，避免 OOM 和导致速度／响应退化的换页。统一内存设备的共享分配不重复计入物理占用。减少冗余分配和搬运仍以实际速度收益为依据，不以省内存为由牺牲已验证的加速。端到端、各阶段、冷加载、每窗及至少 5 次热运行按 [性能协议](performance.md) 留存原始记录。首版使用离线文件处理作为测量场景，实时能力以实际 RTF 和响应测量判断。

CLI 与 GUI 使用同一 core 任务接口，提供逐模型及处理链、输入输出位置、模型校验、阶段进度、取消和错误说明。取消至少在每个推理窗口之间检查，停止后不得把不完整文件标成成功输出；窗口内部取消延迟另行测量。未验证的能力保持不可用状态。完成条件仍为四套模型的音频链、质量、性能与两种入口全部通过验收。
