# 任务与验收

状态日期：2026-09-11。当前阶段：RoFormer 真实音频与跨窗验证。三套 VR 的完整 PCM 音频链通过 18 组合成对照，CLI 的三套真实片段对照也已通过；RoFormer 原 FP32 频谱的完整窗误差已定位，采用 v1.1 的 float64 正向频谱后，同一个 8 秒输入通过原有门限。GUI 和完整多模型处理链尚未接通。

## 已明确的需求

| 任务 | 指定权重 | 目标输出 |
| --- | --- | --- |
| 分离伴奏 | `model_bs_roformer_ep_368_sdr_12.9628.ckpt`（viperx 1296） | 人声、伴奏 |
| 分离和声 | `5_HP-Karaoke-UVR.pth`、`6_HP-Karaoke-UVR.pth` | 主唱与和声侧输出，具体映射待参考验证 |
| 去混响与回声 | `UVR-DeEcho-DeReverb.pth` | 干声与残余混响／回声侧输出 |

推理优先纯 Rust，GUI 例外。GUI 按既有目录说明采用 Tauri 与 TypeScript。首版不实现 DeepSeek Harness、MCP 或 AI 问答；不扩展到完整 UVR 模型目录。

运行时不依赖 Python；独立验证工具可使用 Python／PyTorch（2026-09-10 用户确认）。

客户没有提供基线，用户授权本项目决定；采用 [工程基线 v1.3](baseline.md) 的固定参考、参数、误差门限和性能目标。2026-09-11 用户明确要求将推理性能充分压到极限，撤销允许 Rust 慢于 Python 参考的验收标准；两线程只用于固定对照，不限制最终配置。2026-09-12 进一步明确在实际内存可承受的范围内速度优先，撤销固定 4／8 GiB RSS 上限，允许用更多内存换取加速并保留系统余量。关键实验缺少依赖时安装后继续，不以缺包降低目标或排除候选，具体要求见 [性能协议](performance.md#执行方法)。
